# ProXPL PRM Package Registry Specification

**Version**: 1.0.0  
**Endpoint**: `https://proxpl.in/api/registry`  
**Static Fallback**: `https://raw.githubusercontent.com/ProgrammerKR/ProXPL/main/registry/packages.json`

This specification defines the architecture, data structures, authentication model, and client behavior for the ProXPL Repository Manager (PRM) package registry.

---

## 1. Registry Architecture Overview

```
                      +-----------------------------+
                      |       ProXPL Developer      |
                      +--------------+--------------+
                                     |
                                     | prm install / publish / search
                                     v
                      +-----------------------------+
                      |         PRM CLI Client      |
                      +--------------+--------------+
                                     |
              +----------------------+----------------------+
              |                                             |
              v (REST / JSON API)                           v (Git / Tarball CDN)
+-----------------------------+               +-----------------------------+
|    PRM Registry Service     |               |    Package Source Host      |
|    (https://proxpl.in)      |               |    (GitHub / Tarballs)      |
+--------------+--------------+               +-----------------------------+
               |
               v
+-----------------------------+
|  Package Metadata Catalog   |
|     (packages.json)         |
|  - Semantic Versions        |
|  - SHA-256 Checksums        |
|  - Dependency Graphs        |
+-----------------------------+
```

## 2. Package Manifest (`project.pxcf`)

Every ProXPL package published to the registry must include a valid `project.pxcf` manifest at its root:

```javascript
project {
    name: "http-server"
    version: "1.3.0"
    author: "Your Name <you@example.com>"
    license: "MIT"
    description: "High-performance HTTP server for ProXPL"
    repository: "https://github.com/User/prox-http-server"
    keywords: ["http", "web", "server"]
}

paths {
    src: "./src"
    entry: "src/index.prox"
}

dependencies {
    json: "^1.1.0"
}

engine {
    proxpl: ">=1.5.0"
}
```

## 3. Package Registry Endpoints

### 3.1. Search Packages
- **Route**: `GET /api/registry/search?q={query}`
- **Description**: Searches package names, descriptions, and keywords.
- **Response**:
```json
{
  "total": 1,
  "results": [
    {
      "name": "http-server",
      "version": "1.3.0",
      "description": "High-performance HTTP/1.1 and WebSocket server library",
      "author": "ProXentix Team <packages@proxpl.in>",
      "stars": 42
    }
  ]
}
```

### 3.2. Get Package Information
- **Route**: `GET /api/registry/package/{name}`
- **Description**: Returns all version metadata, tarball URLs, and dependency trees for a specific package.
- **Response**:
```json
{
  "name": "http-server",
  "latest": "1.3.0",
  "versions": {
    "1.3.0": {
      "version": "1.3.0",
      "tarball": "https://github.com/ProgrammerKR/prox-http-server/archive/refs/tags/v1.3.0.tar.gz",
      "checksum": "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "entryPoint": "src/index.prox",
      "dependencies": {
        "json": "^1.1.0"
      }
    }
  }
}
```

### 3.3. Publish Package
- **Route**: `POST /api/registry/publish`
- **Headers**:
  - `Authorization: Bearer <api_token>`
  - `Content-Type: application/json`
- **Payload**:
```json
{
  "name": "my-package",
  "version": "1.0.0",
  "entryPoint": "src/main.prox",
  "tarball": "https://github.com/user/my-package/archive/refs/tags/v1.0.0.tar.gz",
  "checksum": "sha256:..."
}
```

## 4. Security & Integrity Verification

PRM enforces SHA-256 cryptographic verification for every downloaded package:

1. **Download**: Package archive or repository is fetched from the registry URL.
2. **Hash Computation**: SHA-256 hash is computed across all downloaded source files.
3. **Lockfile Check**: Hash is compared against `project-lock.pxcf`.
4. **Mismatch Rejection**: If the hash differs from the lockfile or registry manifest, the install is halted with exit code `1` to prevent supply chain tampering.

## 5. Lockfile Structure (`project-lock.pxcf`)

```javascript
// ProXPL Dependency Lockfile
// Auto-generated by PRM. Do NOT edit manually.

lockfile_version: "1.0"

packages {
    "http-server": {
        version: "1.3.0"
        resolved: "https://github.com/ProgrammerKR/prox-http-server.git"
        integrity: "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
        dependencies: {
            "json": "1.1.0"
        }
    }
    "json": {
        version: "1.1.0"
        resolved: "https://github.com/ProgrammerKR/prox-json.git"
        integrity: "sha256:f2ca1bb6c7e907d06dafe4687e579fce76b37e4e93b7605022da52e6ccc26fd2"
    }
}
```

## 6. PRM CLI Registry Workflow

```bash
# Log in to registry
prm login

# Search for available packages
prm search http

# View package details
prm info http-server

# Install package from registry
prm install http-server

# Publish current project to registry
prm publish
```
